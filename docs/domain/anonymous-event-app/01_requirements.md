# 匿名イベントアプリ — 要件定義

## 受け取った要求

> **「職場の人を気軽に誘えるアプリを作りたい。ランチに誘うのは意外とハードルが高いから、誘いやすく、断りやすくしたい。**
> **匿名で『今日ランチに行きたい。4人集まったら行く』という募集をかけられて、参加がその人数に達したら実施が決まる。誰が言い出したかも、誰が押したかも、成立するまで見えない。集まらなくても誰も傷つかない。**
> **成立したら誰が行くかはみんなに見えて、そこで『ここがいいかも』と店の提案が来る。決まらなければ会社の周りの店リストも見たい。店の情報は Google マップから出してほしい。**
> **行った店には星と一言のレビューを書けるようにして、行き先の選択肢をどんどん増やしたい。レビューは名前が出る。知らない誰かの点数より、一緒に働いている人の『ここ好き』のほうが信用できる。**
> **ランチに限らず、飲み会・スマブラ大会・日付を指定したランニングまで、『2時に行く人〜』くらいの軽さで使いたい。**
> **入口は Slack に流れる URL と、ホーム画面のアイコン。Slack への投稿で立案者がわかってしまわないように。**
> **使うのは、まずは自分の会社ひとつ。」**

## 確認したいこと（質問リスト）

### 匿名と開示

| 質問 | 回答 |
|---|---|
| 成立したら参加者の名前は誰に見えるか | **全体に公開**。終了後も当日中は一覧に残り、翌日からは参加者の履歴にだけ残る |
| 立案者が誰かは開示されるか | **されない。ずっと匿名**。開示後も参加者の一人としてフラットに出る。「誰が取り消したか」も出さない |
| 「断る」という操作はあるか | **作らない**。押さないことが断り。不参加は DB に行として残らない |
| 不成立のイベントの記録はどうなるか | **本人の履歴にだけ残る**。立てたもの・押したものが状態を問わず残り、他人には最初から見えない |
| 不成立を Slack に流すか | **流さない。静かに消える**（「誰も傷つかない」を最優先） |
| イベントの URL を直接踏んだら何が見えるか | 状態と閲覧者で決まる（下表）。**終了翌日以降・不成立・取り消しは「このイベントは終了しました」の一文だけ**——不成立か取り消しかの区別も出さない |
| 開示された名簿から名前が消えることはあるか | **ある。そして見える**（名簿＝いま行く人）。参加を押す前に伝える |
| 匿名が守られる範囲はどこまでか | **アプリの表示とログまで**。会員 ID とセッショントークンはログに出さない。**DB 権限を持つ人に対しては成立しない**（限界として明記する） |
| 開示する名簿の並び順は | **表示名の五十音順**。参加順・ID と相関する並び（先頭＝立案者になる）は禁止。並べるため**表示名の読みを登録時に必須**で受け取る |
| 参加人数の途中経過は見えてよいか | **見せる**。募集中は分数（「いま 2/4」）、成立後は実数（「行く人 5 人」）。誰が押したかは出さない |

**状態と閲覧者ごとの見え方**

| 状態 | 未ログイン／それ以外の会員 | 立案者本人 | 参加者 |
|---|---|---|---|
| 募集中 | 一覧に出る。詳細（タイトル・集合日時・締切・進捗）まで。名前は誰も出ない | ＋「自分が立てた」印 | ＋「参加中」印 |
| 成立 | 一覧に出る。詳細＋名簿・行く人の数・提案 3 件。立案者の区別は無い | ＋本人向けの印 | ＋本人向けの印 |
| 終了（当日） | 一覧の末尾に「終了」として出る。中身は成立と同じ | 同じ | 同じ |
| 終了（翌日以降） | 一文だけ。一覧に出ない | 履歴から詳細を開ける | 履歴から詳細を開ける |
| 不成立 | 一文だけ。一覧に出ない | 履歴に残る | 押した人の履歴に残る |
| 取り消し | 一文だけ。一覧に出ない | 履歴に残る | 押した人の履歴に残る |

一文だけの画面には「ログインすると、参加していたイベントは履歴で見られます」を添える（状態を漏らさない）。

### 成立のルール

| 質問 | 回答 |
|---|---|
| 「4人集まったら」に立案者は含むか | **含む**（立案者込みの合計人数で数える） |
| 締切はどう決まるか | **立案者が設定。既定は集合日時**。範囲は現在 < 締切 ≦ 集合日時。店の予約が要るときは手前に設定する |
| 成立後の取り消し・あと乗り | **両方 OK**（集合日時まで）。人数を下回っても成立は取り消さない |
| 締切は集合日時より後にできるか | **できない**。「始まってから成立する」状態を作らない |
| 成立はいつ判定されるか | **参加を受け付けたその場で即時**。バッチが動かすのは締切→不成立、集合日時→終了、期限切れセッションの掃除だけ |
| 参加できるかは何で決まるか | **状態と現在時刻の両方**。募集中は締切まで、成立後は集合日時まで。**その時刻ちょうどは締まっている** |
| 成立が二重に起きないか | **起きない**。「まだ募集中」を条件にした更新にし、成功した 1 回だけ Slack に流す |
| 「開催が終わった」はいつか | **集合日時を過ぎたら終了**（終了時刻の概念は持たない）。当日中は「終了」として一覧に残す |
| 成立人数の下限は | **2〜50 人（立案者込み）**。2 人だと相手から立案者が確定するが許容する |
| 公開後のイベントは編集できるか | **できない**（取り消して立て直す）。公開前に確認画面を 1 枚置き、参加 0 件の取り消しは Slack に流さない |
| 立案者は自分の参加だけ取り消せるか | **募集中は不可、成立後は他の参加者と同じ**。禁止の理由（立案者不在の募集が続く）が効くのは募集中だけ |
| 定員（上限人数）はあるか | **持たない**。あと乗り自由と整合させる |
| 立案者はイベントをやめられるか | **「イベントの取り消し」として扱う**（集合日時まで）。成立前後を問わず bot が流す（誰がは出さない） |

### 利用範囲と規模

| 質問 | 回答 |
|---|---|
| 誰までがイベントを見られるか。将来の規模は | **1 社で使う。閲覧は URL を知っている人なら誰でも**（一覧・詳細・店リスト・レビューまで）。**参加・立案・レビュー投稿はログイン必須**。マルチテナントは今回やらない |
| 会員登録は誰でもできるか | **制限を作らない**。根拠は「URL が出るのは社内 Slack だけで、混入したら DB 直接対応で止める」 |
| 会社の座標・bot などの設定は誰が管理するか | **設定ファイル（エンジニア作業）**。座標は git 管理、**bot トークンは環境変数**（失効・ローテーションがある）。起動時に両方を検証する |
| DB 直接対応は具体的にどうやるか | 踏み台経由の read-only を既定とし、更新は別ロール。**実施は 2 人**（実行者と確認者）。SQL と件数を記録し、削除より `state` の更新を第一手段にする |
| 苦情・問い合わせは誰が受けるか | **オーナー部署・一次受け（Slack チャンネル）・引き継ぎ先を決めておく**。機能は作らない |
| 費用の上限は誰が見るか | **月額上限と、止める人を決める**。予算アラートと 1 日のクォータ上限を設定。Google 呼び出しは 2 秒でタイムアウト、連続失敗でフォールバック |
| バックアップと復旧はどうするか | 頻度・保持期間・戻せる範囲を決める。**復旧すると取り消した参加が復活する**ので、手順に是正を含める |
| 時刻の基準は何か | **すべて JST。日付の境界は JST の 00:00**（「当日中」もこれ）。起動時に JVM・DB・コンテナのずれを検証する |
| 公開ページのキャッシュはどうするか | 一覧・詳細は `private, no-store`。同じ URL の中身が状態と閲覧者で変わるため、中間キャッシュに残さない |
| 不適切なレビュー・イベントへの対処は | **今回は作らない**。本人が自分のものを消せるだけで、問題が起きたら DB 直接対応 |

### 店とレビュー

| 質問 | 回答 |
|---|---|
| 店は誰がどう登録するか | **Google Places の検索結果から選ぶ**。API に無い店・社食は手動でも登録できる。レコードは最初のレビュー時に作り、店名は**会員が確定した呼び名**として保存する |
| 同じ店が二重に登録されるのを防げるか | **手動登録の前に既存の店を前方一致で出して「これですか？」と聞く**。表記揺れは止まらないと割り切る（統合の操作は作らない） |
| 店名を誰かが上書きしたらどうなるか | **誰でも直せる**。更新時に手元の更新日時を突き合わせ、先に直されていたら弾く。変更前の値は残さない |
| 「周辺の店リスト」とは何か | **会社の座標を基準に Google Places で周辺検索した結果**＋登録済みの店とレビュー。会員個人の位置情報は使わない |
| Google Places の課金・規約 | 従量課金（社内規模なら無料枠内の想定）。**無期限に保存してよいのは place_id だけ**（店名の持ち方は 03 で扱う） |
| レビューの多重度・形 | **行くたびに書ける**。項目は**星（5段階）と一言だけ**。自分のレビューは編集・削除でき、履歴の「自分のレビュー」から開く |
| 「ここがいいかも」の提案はどう出るか | **アプリが自動で出す**。成立したイベントの詳細画面に常に 3 件。並べ方は社内レビューの評価順で、足りない分は Google で補う（手動提案は作らない） |
| 立案時に店を選べるか | **選べない**。場所を伝えたいときはタイトルに書く |
| 店の「決定」という操作はあるか | **作らない**。行き先は会話で決め、アプリには記録しない |
| レビューはイベントに紐づくか | **紐づけない**。イベントを経由しなくても書ける |
| 実名レビューから匿名参加が推測される問題 | **許容する**。成立時点で参加者は全体公開されるため |

### 入口・通知

| 質問 | 回答 |
|---|---|
| Slack へは誰が投稿するか | **bot が自動投稿**。立案者は一切露出しない。投稿先チャンネルは立案時に選べる |
| 成立・不成立の通知はどこへ | **成立と取り消しだけ bot が流す**（人数のみ）。**不成立は何も流さない**。名前の開示はアプリ内で見る |
| bot の投稿に失敗したら | **3 回まで再試行して諦める**（投げ直す仕組みは作らない）。イベントは公開のままで、作成完了画面に失敗と URL のコピーを出す |
| アプリの形態 | **インストール不要の Web アプリ**。ホーム画面にショートカットを置ける |
| 自分の参加を自分に見せるか | **見せる**。一覧の各行に本人向けの印（参加中／成立した）を出し、履歴への入口を一覧と同じ階層に置く |
| 毎日立てる人の手間を減らすか | **減らす**。「前回と同じ内容で立てる」を用意し、既定は成立人数 4 人・前回のチャンネル・締切＝集合日時 |
| 匿名の範囲を利用者にどう伝えるか | **説明ページは作らず、画面に 2 行**——「匿名なのは成立するまで」「成立すると参加者全員の名前が出る（立案者もその中にいる）」。初回ログイン時にも出す |
| 一覧の並び順は | **集合日時の昇順**（終了当日は末尾）。「あと一人で成立」が目に入る順にする |

### 参加しない人に見えるもの

押さない側から見た要件。**進捗・名簿・bot 投稿を横断して 1 回だけ判断する。**

| 質問 | 回答 |
|---|---|
| 「断りやすい」とは何を満たすことか | **①記録が残らない（満たす）②押さないことが目立たない（満たさない）**。進捗も名簿も公開なので、小さな集まりでは「押していないのは自分だけ」が計算できる |
| 押していない人に進捗が見えることは | **許容する**。進捗の公開は「あと一人で成立」で背中を押すためで、要求の中心にある |
| 進捗の変化を定点観測されることは | **許容する**。粗い段階表示にすれば防げるが、背中を押す価値を削る |
| 不成立で一覧から消えるのを定点観測されることは | **許容する**。当日中は一覧に残せば消滅の観測点は消えるが、不成立と終了を同じに見せる複雑さは持たない |
| 名簿に名前が無いことで「行っていない」が分かることは | **許容する**。機能では閉じられない |
| 投稿先チャンネルを選べることは | **許容する**。実質の招待制になりうるが、立案の自由を残す |
| bot の投稿が流れ続けることは | **許容する**。ミュートは Slack 側の機能に任せる |
| タイトルに他人の名前を書かれたら | **「タイトルに他人の個人名を書かない」をルールとして明記する**。窓口は苦情の一次受けとし、対応は DB 直接対応で消す |
| 誘いを見ずに店情報だけ使えるか | **使える**。店リストへは一覧を通らずに開ける導線を置く |

## 業務フロー

```
[運営者（管理者）]
 0. 会社の座標・Slack bot を設定する（設定ファイル。画面は作らない・初回のみ）

[立案者（匿名）]
 1. ログインし、イベントを立てて公開する（内容・集合日時・成立人数・締切・投稿先チャンネル。既定値が入っていて、投稿の前に確認画面で 1 回止まる）。公開した時点で、自分が参加の1人目になる
 2. 間違えたときは取り消して、立て直す（公開後の編集はできない）
 3. やめたくなったら、集合日時までイベントを取り消せる（終了・不成立のあとは取り消せない）

[bot（Slack・外部）]
 4. 公開されたら、選ばれたチャンネルへ URL を投稿する（立案者の名前はどこにも出ない）。投稿の記録をイベント側に写す
 5. 成立したときだけ、元の投稿につなげて結果を流す（人数のみ）
 6. 取り消されたときは「このイベントは取り消されました」を流す（誰がは出さない。参加0件のあいだは流さない）

[参加したい人]
 7. Slack の URL かホーム画面のショートカットから開き、イベントの一覧・詳細を見る（ここまでログイン不要。集合日時が近い順・進捗つき）
 8. 「参加」を押す（ここでログイン。誰が押したかは成立まで誰にも見えない）
 9. 気が変わったら取り消す。もう一度参加してもよい（どちらも集合日時まで）

[システム]
10. 参加が登録されたその場で人数を判定し、成立人数に達したら即時に成立・名前の開示を行う（誰が立案者かは出さない。名簿は表示名の五十音順）
11. 【バッチ】締切を過ぎても達していなければ、不成立にする（判定が重なったときは成立を優先）
12. 【バッチ】集合日時を過ぎたら、終了にする（当日中は一覧に残り、翌日からは履歴だけ）。期限切れのセッションも消す

[参加者（成立後）]
13. 詳細画面に出ている店の提案（3 件）を見る（「決定」の操作はなく、行き先は会話で決める）
14. 決まらなければ、会社周辺の店リストを見る。API に無い店・社食は、最初のレビューを書くときに手で登録する
15. あと乗りする人・取り消す人が出てもよい（集合日時まで。人数を下回っても成立のまま）
16. 行ったあと、店に星（5段階）と一言を実名でレビューする。自分のレビューはあとから直せる・消せる

[Google Places（外部）]
17. 店リストが開かれたら、会社の座標の周辺の店を検索して返す

[例外・ルール]
 - 誰が立てたか・誰が押したかは成立するまで見えない。立案者は成立後も一切出ない
 - 開示する名簿は表示名の五十音順（参加順・作成時刻と相関する並びにしない）
 - 現在 < 締切 ≦ 集合日時。過去の集合日時では立てられない。公開後の編集はできない
 - 参加できるかは状態と現在時刻の両方で決まる。その時刻ちょうどは締まっている
 - 成立人数は 2〜50 人（立案者込み）。二重参加はできず、取り消してからの再参加は自由
 - 立案者が自分の参加だけを取り消せるのは成立後。人数を下回っても成立のまま
 - 進捗の分数は募集中だけ。成立後は実数だけを出す
 - bot の投稿は 3 回で諦める。失敗してもイベントは公開のまま
 - 時刻はすべて JST。会員の識別子とセッショントークンはログに出さない
 - 閲覧はログイン不要、書き込みはログイン必須
```
