# 匿名イベントアプリ — 要件定義

## 受け取った要求

> **「職場の人を気軽に誘えるアプリを作りたい。ランチに誘うのは意外とハードルが高いから、誘いやすく、断りやすくしたい。**
> **匿名で『今日ランチに行きたい。4人集まったら行く』という募集をかけられて、参加がその人数に達したら実施が決まる。誰が言い出したかも、誰が押したかも、成立するまで見えない。集まらなくても誰も傷つかない。**
> **成立したら誰が行くかはみんなに見えて、そこで『ここがいいかも』と店の提案が来る。決まらなければ会社の周りの店リストも見たい。店の情報は Google マップから出してほしい。**
> **行った店には星と一言のレビューを書けるようにして、行き先の選択肢をどんどん増やしたい。レビューは名前が出る。知らない誰かの点数より、一緒に働いている人の『ここ好き』のほうが信用できる。**
> **ランチに限らず、飲み会・スマブラ大会・日付を指定したランニングまで、『2時に行く人〜』くらいの軽さで使いたい。**
> **入口は Slack に流れる URL と、ホーム画面のアイコン。Slack への投稿で立案者がわかってしまわないように。**
> **使うのは、まずは自分の会社ひとつ。」**

## 確認したいこと（質問リスト）

### 匿名と開示

| 質問 | 今回の回答（仮） |
|---|---|
| 成立したら参加者の名前は誰に見えるか | **成立したら全体に公開**（誰が行くかを全員が見られる）。終了後も**当日中は「終了」として一覧に残り**、翌日からは参加者の履歴にだけ残る【確定】 |
| 立案者が誰かは開示されるか | **されない。立案者はずっと匿名**。開示後も参加者の一人としてフラットに表示され、「誰が言い出したか」は永遠に出ない。成立後にイベントが取り消された場合も「誰が取り消したか」は出さない【確定】 |
| 「断る」という操作はあるか | **作らない**。参加を押さないことが断り。不参加という記録自体が存在しないので、断ったことは誰にも（システムにも）わからない【確定】 |
| 不成立のイベントの記録はどうなるか | **本人の履歴にだけ残る**。「自分が立てたもの」「参加を押したもの」の両方が、成立・不成立・取り消しを問わず自分の履歴に残る。他人には最初から最後まで見えない【確定】 |
| 不成立を Slack に流すか | **流さない。静かに消える**。イベント時の投稿はそのまま（アプリを開けば終了していることはわかる）。「誰も傷つかない」を最優先【確定】 |
| イベントの URL を直接踏んだら何が見えるか | 状態と閲覧者で決まる。**募集中・成立・終了当日は誰でも詳細まで見える**（成立後は名前も＝全体公開どおり）。**終了の翌日以降・不成立・取り消しは「終了したイベントです」の骨だけ**——見えるのは既存ルールどおり参加者（終了）／本人（不成立・成立前取り消し）がログインしたときのみ。Slack に URL が残り続けても翌日以降に名前は漏れない【確定】 |
| 参加人数の途中経過は見えてよいか | **人数の進捗だけ見せる**（「いま 2/4」）。イベント一覧でも詳細でも表示する（あと一人で成立、が見えて参加の背中を押す）。誰が押したかは見せない【確定】 |

### 成立のルール

| 質問 | 今回の回答（仮） |
|---|---|
| 「4人集まったら」に立案者は含むか | **含む**。立案者込みの合計人数で数える【確定】 |
| 締切はどう決まるか | **立案者がイベント時に設定。既定は集合時刻**。届かなければその時点で不成立【確定】 |
| 成立後の取り消し・あと乗り | **両方 OK**。取り消しでしきい値を下回っても成立は取り消さない（行くかどうかは当日の人たちに任せる）。できるのはどちらも集合時刻まで【確定】 |
| 締切は集合時刻より後にできるか | **できない**。締切 ≦ 集合時刻。「始まってから成立する」という状態を作らない【確定】 |
| 「開催が終わった」はいつか | **集合時刻を過ぎたら終了**（終了時刻・所要時間の概念は持たない。あと乗り・取り消しもここまで）。ただし表示は**当日中は「終了」ラベル付きで一覧に残す**——集合直後に「誰が来るんだっけ」を一覧からすぐ開けるように。翌日からは参加者それぞれの履歴にだけ残る【確定】 |
| 成立人数の下限は | **2 人以上（立案者込み）**。1 人ではイベントの意味がない【確定】 |
| 公開後のイベントは編集できるか | **できない**。間違えたら取り消して立て直す。「参加したあとに条件が変わる」問題がそもそも起きない【確定】 |
| 定員（上限人数）はあるか | **持たない**。あと乗り自由と整合させ、今回は作らない【確定】→ 03 付録A（今回やらないこと）に載せる |
| 立案者はイベントをやめられるか | **「イベントの取り消し」として扱う**。専用の「取り下げ」概念は作らない。**取り消しは成立前・成立後を問わず bot が Slack に知らせる**（誰が取り消したかは出さない）——URL は Slack に流れたままなので、黙って消すと参加しようと押した人が迷う。アプリ内では、成立前の取り消しは本人の履歴にだけ残り、成立後の取り消しは参加者にも見える【確定】 |

### 利用範囲と規模

| 質問 | 今回の回答（仮） |
|---|---|
| 誰までがイベントを見られるか。将来の規模は | **1社で使う。閲覧は URL を知っている人なら誰でも**——Slack に流れた URL を開けば、ログインなしでイベントの一覧・詳細・店リスト・レビューまで見られる。**参加・立案・レビュー投稿はログイン必須**（本人の履歴を残すため）。グループ分け・マルチテナントは今回やらない【確定】 |
| ユーザー登録は誰でもできるか | **既存のメール＋パスワード登録をそのまま使い、今回は制限を作らない**。ドメイン制限・招待制は今回やらないことに明記（URL を知っている人しか来ない前提）【確定】 |
| 会社の座標・bot などの設定は誰が管理するか | **設定ファイル（エンジニア作業）で済ませる**。管理画面・管理者ロールは今回作らない。変更頻度がほぼゼロのため【確定】 |
| 不適切なレビュー・イベントへの対処は | **今回は作らない**。本人が自分のものを消せるだけ。通報・強制削除の仕組みは作らず、問題が起きたら DB 直接対応【確定】 |

### 店とレビュー

| 質問 | 今回の回答（仮） |
|---|---|
| 店は誰がどう登録するか | **基本は外部 API（Google Places）の検索結果から選ぶ**。API に無い店・社食・オフィス内の場所は手動でも登録できる。店のレコードは最初にレビューが書かれるときに作る——Google の検索結果を選ぶと店名がフォームに転記され、**会員が確定した呼び名**として保存する（共有マスタなので誰でも直せる）【確定】 |
| 「周辺の店リスト」とは何か | **会社の座標（設定として1つ登録）を基準に Google Places で周辺検索した結果**＋登録済みの店とそのレビュー。ユーザー個人の位置情報は使わない【確定】 |
| Google Places の課金・規約 | 従量課金（社内規模なら無料枠内の想定）。**規約上、店名等のキャッシュに期限がある**ため、無期限に保存してよいのは place_id。レビュー表示用に店名をどう持つかは詳細設計の論点にする【確定】→ 03 付録B（判断の記録）で扱う |
| レビューの多重度・形 | **行くたびに書ける**（1人1店に複数可）。項目は**星（5段階）と一言だけ**。「何時頃に行って並んだか」は一言の中に自由に書く（構造化しない）。自分のレビューは編集・削除可【確定】 |
| 「ここがいいかも」の提案はどう出るか | **アプリが自動で出す**。成立（開示）のタイミングで、社内レビューの評価が高い店を **3 件程度** 提案する（レビューが少ないうちは Google の評価・近さで補完）。**参加者からの手動提案は作らない**【確定】 |
| 立案時に店を選べるか | **選べない（今回やらない）**。場所を伝えたいときはタイトルに書く（「今日ランチ@サイゼ」）。イベントは店への参照を持たない【確定】 |
| 店の「決定」という操作はあるか | **作らない**。アプリは提案とレビューを見せるだけで、どこに行くかは会話で決める。行き先はイベントに記録されない【確定】 |
| レビューはイベントに紐づくか | **紐づけない**。イベントを経由しなくても書ける。「食べたらそのまま書ける」は画面の導線の話とする【確定】 |
| 実名レビューから匿名参加が推測される問題 | **許容する**。成立時点で参加者は全体公開されるので、実質的な追加リスクは小さい【確定】 |

### 入口・通知

| 質問 | 今回の回答（仮） |
|---|---|
| Slack へは誰が投稿するか | **bot が自動投稿**。立案者は一切露出しない。**投稿先チャンネルは立案時に選べる**（bot が入っているチャンネルの中から）【確定】 |
| 成立・不成立の通知はどこへ | **成立したときと、取り消されたとき（成立前後を問わず）に bot が Slack に投稿**（人数のみ。名前は出さない）。**不成立だけは何も流さない**（締切で自然に終わるため。「誰かの誘いが流れた」を可視化しない）。名前の開示はアプリ内で見る【確定】 |
| アプリの形態 | **インストール不要の Web アプリ**。URL を開けばそのまま使える。スマートフォンのホーム画面にショートカット（ホーム画面に追加）を置けて、企画の一覧や店リストを見たいときにいつでも開ける【確定】 |

## 業務フロー

```
[運営者（管理者）]
 0. 会社の座標・Slack bot・投稿先チャンネルを設定する（設定ファイル。画面は作らない・初回のみ）

[立案者（匿名）]
 1. ログインし、イベントを立てて公開する（内容・集合日時・成立人数（自分込み・2人以上）・締切（既定＝集合時刻）・店（任意）・投稿先チャンネル）。公開した時点で、自分が参加の1人目になる
 2. 間違えたときは取り消して、立て直す（公開後の編集はできない）
 3. やめたくなったら、いつでもイベントを取り消せる

[bot（Slack・外部）]
 4. 公開されたら、選ばれたチャンネルへ URL を投稿する（立案者の名前はどこにも出ない）。投稿の記録（channel / message の ID）をイベント側に写す
 5. 成立したときだけ、元の投稿につなげて結果を流す（人数のみ）
 6. 取り消されたときは（成立前・成立後を問わず）「このイベントは取り消されました」を流す（誰が取り消したかは出さない）

[参加したい人]
 7. Slack の URL かホーム画面のショートカットから開き、イベントの一覧・詳細を見る（ここまでログイン不要。進捗「いま 2/4」が見える）
 8. 「参加」を押す（ここでログイン。誰が押したかは成立まで誰にも見えない）
 9. 気が変わったら取り消す。もう一度参加してもよい（どちらも集合時刻まで）

[システム（バッチ）]
10. 参加数が成立人数に達したら、成立にして参加者（立案者含む）の名前を開示する（誰が立案者かは出さない）。あわせて「ここがいいかも」の店の提案を 3 件程度添える（社内レビューの評価が高い順。足りなければ Google の評価・近さで補完）
11. 締切を過ぎても達していなければ、不成立にする（記録は各自の履歴のみ。Slack には流さない）
12. 集合時刻を過ぎたら、終了にする（当日中は「終了」として一覧に残り、翌日からは参加者それぞれの履歴だけに残る）

[参加者（成立後）]
13. 開示と同時に届いた店の提案（3 件程度）を見る（「決定」の操作はなく、行き先は会話で決める）
14. 決まらなければ、会社周辺の店リスト（Google Places の検索結果＋みんなのレビュー）を見る。API に無い店・社食は手で登録する
15. あと乗りする人・取り消す人が出てもよい（集合時刻まで。人数を下回っても成立のまま）
16. 行ったあと、店に星（5段階）と一言を実名でレビューする（何時頃に行って並んだかは一言の中に書く）。自分のレビューはあとから直せる・消せる

[Google Places（外部）]
17. 店リストが開かれたら、会社の座標の周辺の店を検索して返す

[例外・ルール]
 - 誰が立てたか・誰が参加を押したかは、成立するまで誰にも見えない（人数の進捗だけ見える）
 - 立案者が誰かは、成立後も含めて一切出ない（開示後は参加者の一人として表示されるだけ）
 - 締切 ≦ 集合時刻。過去の集合時刻ではイベントを立てられない
 - 締切を過ぎたイベントには参加を押せない（不成立で確定する）
 - 成立人数は 2 人以上（立案者込み）。公開後のイベントは編集できない（取り消して立て直す）
 - 同じイベントに同じ人が 2 回参加はできない。取り消してからの再参加は自由
 - 成立後に取り消しでしきい値を下回っても、成立は取り消さない
 - 不成立は、本人の履歴以外のどこにも表示されず、Slack にも流れない
 - 取り消しは成立前・成立後を問わず Slack に流れる（誰が取り消したかは出ない）。アプリ内では、成立前の取り消しは本人の履歴のみ、成立後の取り消しは参加者にも見える
 - 終了したイベントは、当日中は「終了」として一覧に残り、翌日からは参加者それぞれの履歴にだけ残る
 - 閲覧（一覧・詳細・店リスト・レビュー）はログイン不要。参加・立案・レビュー投稿はログインが必要
 - URL を直接踏んだ場合も見え方のルールは同じ。終了の翌日以降・不成立・取り消しのイベントは「終了したイベントです」の骨だけ返し、詳細と名前は資格のある人（参加者／本人）のログイン時のみ
 - 店の提案はアプリの自動のみ（参加者からの手動提案は作らない）
 - Google Places が使えないときは、登録済みの店とレビューだけで店リストを出す（誘い自体は店なしで回る）
```
