## コンテキストの判断

| 日常的に書き換える人 | 何を書き換えるか | 更新の頻度 | 見る画面 |
|---|---|---|---|
| 社員 | 参加を押す・取り消す・レビューを書く | 毎日〜週数回 | スマホの Web アプリ |
| 社員（立案者の役割） | 募集の作成・取り消し | 不定期 | 同上 |
| 運営者 | 会社の座標・bot 設定 | ほぼ初回のみ | 画面なし（設定ファイル） |

**判断：** コンテキストは 3 つ——**会員**（既存 `edu.customer` をそのまま）／**イベント**（誘い・参加・成立）／**店**（店とレビュー）。記号名（パッケージ名）は段階 6 で評価して決める。

**理由：** 人間のアクターが社員 1 種しかなく「担当者」軸が無効なため、残りの軸で切った。変更の理由（認証／誘いのルールの改善／Google Places 連携）・ライフサイクル（年単位／数時間で終わる揮発／無期限のストック）・公開性（秘匿／匿名絡み／全実名公開）が 3 列とも違う。会員は既存資産で分離済み、「レビューはイベントに紐づけない」決定により店の世界はイベントを知らずに完結し、参照は ID のみ・一方向で循環なし。詳細な検討は [00_memo.md](./00_memo.md)。
