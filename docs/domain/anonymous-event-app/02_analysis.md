# 匿名イベントアプリ — 思考過程（メモ・提出しない）

## 名詞と動詞

**動詞**（先に拾う・能動形にそろえた）：設定する、ログインする、募集を作る、公開する、取り消す（募集を）、立て直す、参加する、参加を取り消す、再参加する、成立にする、不成立にする、終了にする、開示する（名前を）、投稿する（bot が URL・結果を）、写す（投稿の記録を）、提案する（システムが店を）、検索する（Google が周辺を）、登録する（店を）、レビューを書く、編集する（レビューを）、削除する（レビューを）、ログアウトする、見る（一覧・詳細・進捗・履歴・店リスト・レビュー・開示された名前を）、数える（進捗を）、判定する（人数に達したか・締切/集合時刻を過ぎたか）

**名詞**：社員、会員、アカウント、立案者、参加者、閲覧者、運営者、募集、イベント、内容（タイトル）、イベントの種類（ランチ・飲み会・ランニング…）、集合日時、締切、成立人数（しきい値）、進捗（いま 2/4）、参加、参加の記録、取り消し、成立、不成立、終了、開示、名前、匿名、本人の履歴、Slack、チャンネル、URL、投稿の記録（channel / message の ID）、ホーム画面ショートカット、bot、店、店リスト、周辺、会社の座標、place_id、店名、レビュー、星（5段階）、一言、評価、店の提案（3件）、Google Places、メールアドレス、パスワード、セッション

動詞を 2 つに分けます（どちらでもない「モデルに向かわない」ものは、捨てずに 3 行目に残します）。

| 種類 | 動詞 | 行き先 |
|---|---|---|
| **状態を変える** | イベントを立てる・公開する / 取り消す / 成立にする（参加が引き金・即時） / 不成立にする・終了にする（時間が引き金） | **イベント**。立てた瞬間に立案者の参加が 1 件できる |
| 〃 | 参加する / 参加を取り消す / 再参加する | **参加** |
| 〃 | 店を登録する（最初のレビュー時に Google の結果から転記して会員が確定／手動も可） | **店** |
| 〃 | レビューを書く / 編集する / 削除する | **レビュー** |
| 〃 | ログインする / ログアウトする | **セッション** |
| 〃 | 写す（Slack 投稿の記録を） | イベントの属性（外部の相手側 ID の写し） |
| **値を返す** | 見る（一覧・詳細・履歴・店リスト・名前）/ 数える（進捗 2/4）/ 判定する（人数・締切・集合時刻）/ 提案する（店を 3 件） | モデルのメソッド。**どれも保存しない** |
| **モデルに向かわない** | 設定する（運営者）/ 検索する（Google が周辺の店を）/ 投稿する（bot が Slack へ） | 設定ファイルと外部 API。モデルは増えない（投稿のうちこちらに書く分は「写す」に分解済み） |

> ここで注目したいのは、**イベントの状態を動かす主語が 3 種しかない**こと——立案者（取り消し）、会員の参加（成立の引き金）、バッチ（不成立・終了、あわせて期限切れセッションの掃除）です。成立だけは人の操作の中で即時に起きますが、それも「参加が 1 行増えた結果」であって成立という操作は誰も持っていません。残りの遷移は**時間が動かします**。教材の注文のような「調理を始める」型の操作はここには無く、会員がやるのは参加とレビューという「行を足す・消す」操作で、これは記入例の「休みにする＝レコードを 1 行足す」と同じ形です。

## ふるい分け

| 名詞 | 仕分け | 理由 |
|---|---|---|
| イベント | **エンティティ** | アプリの中心。ID で区別し、作られ・成立し・終わるライフサイクルがある。同じ内容のイベントが 2 件あっても別物 |
| 参加 | **エンティティ** | 誰がどのイベントに押したか。個別に増減し、本人の履歴として追跡する。成立判定の数え上げ元 |
| 店 | **エンティティ** | レビューと提案の紐づけ先。place_id への参照＋会員が確定した呼び名を持ち、手動登録もある。無期限に残る |
| レビュー | **エンティティ** | ID で区別。行くたびに増え、本人が編集・削除する。無期限に残る |
| 会員 | **エンティティ** | ログインする本人。ID で区別し、参加・レビュー・履歴すべての起点（「社員」「アカウント」と言い換えない） |
| パスワード | **エンティティ** | 認証情報。会員本体と分けて持つ（変更のタイミングも漏えい時の扱いも別物） |
| セッション | **エンティティ** | ログインしている状態。トークンで識別し、ログアウトで消えるライフサイクルがある |
| メールアドレス | 属性 | 会員の一部（ログイン ID） |
| 公開用 UUID（会員） | 属性 | 会員の一部。開示・レビュー表示の API で会員を指す識別子（連番 id を外に晒さない） |
| 立案者 | 属性 | イベントの一部（作成者＝会員への参照）。匿名は「表示しない」だけで、参照自体は持つ |
| 内容（タイトル） | 属性 | イベントの一部 |
| 集合日時 | 属性 | イベントの一部 |
| 締切 | 属性 | イベントの一部（既定＝集合時刻） |
| 成立人数（しきい値） | **値オブジェクト候補** | 中身 1 つ（2 以上の整数）。制約を型で持たせるなら OpaqueValue、モデルの形を書くときに決める |
| イベントの状態 | 属性（状態） | 募集中・成立・不成立・終了・取り消しの 5 値は 1 つの状態の値。状態遷移であって独立した概念ではない |
| 投稿の記録 | 属性 | イベントの一部。外部（Slack）の相手側 ID（channel / message）の写し |
| チャンネル | 属性 | イベントが持つ投稿先。チャンネルの一覧自体は Slack から都度取得（保存しない） |
| 公開用ID | 属性 | イベントの一部。連番 ID を晒さず URL に使う識別子 |
| 星（5段階） | **値オブジェクト候補** | 中身 1 つ（1〜5）。同じ 4 は同じ 4。制約を型で持つかはモデルの形を書くときに決める |
| 一言 | 属性 | レビューの一部 |
| 名前 | 属性 | 会員の一部（開示・レビューで表示する。拾い漏れをここで追加） |
| place_id | 属性 | 店の一部。Google の店への外部参照 |
| 店名 | 属性 | 店の一部。会員が確定した呼び名（登録時に Google から転記・誰でも直せる） |
| 役割（立案者・参加者） | 対象外 | アクターの役割であってモデルではない。実体は会員と参加 |
| 閲覧者 | **対象外** | ログインすらしない。記録が存在しない |
| 運営者 | **対象外** | 設定ファイルで済ませると確定。モデルに現れない |
| 進捗（いま 2/4） | **対象外（＝計算）** | 参加の記録を数えれば出る。保存すると参加のたびに二重管理になる |
| 開示 | **対象外** | 「成立にする」の結果であって独立した操作・データではない |
| 匿名 | **対象外** | データではなく表示ルール（誰に何を見せるか） |
| 本人の履歴 | **対象外（＝計算）** | 自分が立てたイベント＋押した参加から導出できる。専用テーブルは持たない |
| 店リスト | **対象外（＝検索結果）** | Google Places の呼び出し結果＋登録済みの店。保存しない |
| 周辺 | **対象外（＝検索条件）** | 会社の座標を基準にした検索の条件。データではない |
| 評価（店の平均点） | **対象外（＝計算）** | レビューから毎回計算。保存すると書き込みのたびにズレる |
| 店の提案（3件） | **対象外（＝計算）** | 表示のたびにレビュー高評価順で計算する。成立時の 3 件は保存しない——揮発データのイベントに提案だけ残るねじれを避ける。最新レビューも反映される【確定】 |
| イベントの種類（ランチ・飲み会…） | **対象外** | 要求文の例示にすぎない。カテゴリ分け・絞り込みの要求はなく、タイトルで表現できる。要るとなったら後から足せる（少ない方に倒す）【確定】 |
| Slack | **対象外** | 外部システム。写すのは投稿の記録だけ |
| Google Places | **対象外** | 外部システム。無期限に持つ外部由来は place_id だけ（店名は会員の入力） |
| bot | **対象外** | こちら側の仕組み（部品）であってデータではない |
| ホーム画面ショートカット | **対象外** | ブラウザの機能。システムの外 |
| 会社の座標 | **対象外** | 設定値（設定ファイル）。モデルではない |
| 当日（終了イベントの表示期限） | **対象外** | 表示ルール。集合日時から計算できる |

（拾った名詞をすべて載せた。対象外 18 件。統一前の別名——募集・社員・アカウント・URL・参加の記録——は統一先の行に含む）

## 名前を並べて確認する

名前順に並べて、一族が隣り合うことを確認した。

```
Event            event
EventEntry       event_entry
Member           member
MemberPassword   member_password
MemberSession    member_session
Place            place
PlaceReview      place_review
```

- `Event`/`EventEntry`、`Member` 一族、`Place`/`PlaceReview` がそれぞれ固まって並ぶ
- テーブル名はコンテキストのパス＋エンティティ名。エンティティ名がコンテキスト名で始まるので重ねない（`event_event` にしない）。すべて単数形

## コンテキストの判断

| 日常的に書き換える人 | 何を書き換えるか | 更新の頻度 | 見る画面 |
|---|---|---|---|
| 会員 | 参加を押す・取り消す・レビューを書く | 毎日〜週数回 | スマホの Web アプリ |
| 会員（立案者の役割） | イベントの作成・取り消し | 不定期 | 同上 |
| 運営者 | 会社の座標・bot 設定 | ほぼ初回のみ | 画面なし（設定ファイル） |

**判断：** コンテキストは 3 つ——**会員** `member`（アカウント・認証）／**イベント** `event`（誘い・参加・成立）／**店** `place`（店とレビュー）。パッケージは `edu.member` / `edu.event` / `edu.place`。

**理由：** 人間のアクターが会員（社員本人）1 種しかなく「担当者」軸が無効なため、残りの軸で切った。変更の理由（認証／誘いのルールの改善／Google Places 連携）・ライフサイクル（年単位／数時間で終わる揮発／無期限のストック。**揮発なのは表示と締切の既定が当日を前提にしているという意味**で、数日先のイベントも立てられる——行そのものは消さない）・公開性（秘匿／匿名絡み／全実名公開）が 3 列とも違う。「レビューはイベントに紐づけない」決定により店の世界はイベントを知らずに完結し、参照は ID のみ・一方向で循環なし。詳細な検討は [memo.md](./memo.md)。

**`common` は作らない。** 入れてよい 3 条件（業務の操作で変わらない／管理者が別にいる／参照されるだけ）を満たすデータが 1 つもない——候補になりそうな店は、会員が日々登録する運用データ（条件①で落ちる。教材で売り切れが common に入れなかったのと同じ判定）。運営者の所持物（会社の座標・bot 設定）は設定ファイルでモデルに現れないため、参照マスタのテーブル自体が存在しない。設定を将来 DB 管理に昇格させたら、そのとき初めて common を検討する。
